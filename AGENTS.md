# OpenSpec Workflow

This project uses OpenSpec.

For every non-trivial feature or change:

1. Do not implement the request immediately.
2. First inspect the existing project structure and relevant code.
3. Create or update an OpenSpec proposal using the available OpenSpec workflow.
4. Define requirements, affected components, risks, and implementation tasks.
5. Do not begin implementation until the proposal is complete.
6. Implement changes through the OpenSpec task list.
7. Keep the OpenSpec documents synchronized with the actual implementation.

Small fixes such as typos, formatting, or obvious one-line corrections may be implemented directly.

Do not bypass OpenSpec unless the user explicitly asks to skip it.
